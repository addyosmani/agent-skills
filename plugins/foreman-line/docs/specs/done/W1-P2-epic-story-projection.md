# W1-P2 - Epic/Story projection generator

## Intent

Ship the Stage A->B seam of the Foreman Line: the deterministic capability that takes a schema-valid `ShapingResult` emitted by the shipped W1-P1 package (with `epics: []`) and produces a *proposal* filling `ShapingResult.epics` with a two-level Epic/Story tree - one Epic per `ShapingResult`, one Story per `parcelSpecRef`. This is a **projection only**: no Jira registration (W1-P4), no human approval or receipts (W1-P3), no `status` flips. The output is a new, schema-re-validated, RFC 8785-canonicalizable artifact that W1-P3's approval flow consumes. The parcel proves the plan's core claim - specs are the source of truth, the Epic/Story tree is a projection of them (plan D1) - by deriving every tree node from the referenced spec drafts, never from fabricated placeholder values.

No skill and no kickstarter template ship in this parcel (the productized shaping role is W1-P1's; projection is a mechanical downstream step).
- **Stack:** TypeScript, ESM-only. `engines.node >= 24.11.1` (repo-root precedent, defects_lessons #10 - NOT `>=22`). Tests via `node --test` (`npx tsx --test`). Lint/format with `biome`.

- **Standing rule (binding):** ajv's `JSONSchemaType` is banned as a schema authority anywhere in this repo. This parcel authors **no new stage schema** - it re-validates the filled payload against the frozen `shapingResultSchema` (`plugins/foreman-line/contracts/src/stages/a-intake.ts`), imported, never re-declared.

- **Cross-package imports (read-only consumption of already-exported, shipped surfaces; W0-P4 relative-ESM precedent):**
  - From `plugins/foreman-line/contracts/src/index.ts`: the `ShapingResult`, `EpicNode`, `StoryNode` types and `shapingResultSchema` (the frozen emission/re-validation contract). Mechanism: `import ... from '../../contracts/src/index.js'`. `contracts/` is untouched.
  - From `plugins/foreman-line/shaping/src/index.ts`: `readShapingResult` (primary input interface) and `discoverShapingResults` (documented glob fallback). Mechanism: `import ... from '../../shaping/src/index.js'`. `shaping/` is shipped-frozen; **consumed, never modified** - this parcel adds no field, flag, or behavior to it and re-implements neither reader.
  - From `plugins/foreman-line/spec-linter/src/index.ts`: `parseFrontmatter` (frozen frontmatter parser) to read each referenced draft's `title:`. Mechanism: `import ... from '../../spec-linter/src/index.js'`. `spec-linter/` is **consumed, never modified**.

No new `dependencies` entry is required by the relative-import mechanism (W0-P4 precedent). A grep test asserts zero bare `@foreman-line/*` specifiers and that root `package.json` is unmodified.
- **Input contract (consume the shipped W1-P1 readers directly; Q7):**
  - **Primary:** `readShapingResult(path)` from the shipped `shaping` package - the **explicit path handoff is the contract** (W1-P1's ratified P1->P2 interface). This parcel does not re-parse or re-validate the *input* JSON itself; it delegates to the shipped reader (which throws on missing file, unparseable JSON, or a payload failing `shapingResultSchema`).
  - **Fallback:** `discoverShapingResults(repoRoot)` from the shipped package - the documented `active/*.shaping-result.json` glob discovery, not the primary interface.
  - The input's `discoverShapingResults` fallback lists `*.shaping-result.json`; the emitter's own `*.projected.shaping-result.json` output MUST NOT be re-selected as an input (the suffix `.projected.shaping-result.json` also ends with `.shaping-result.json`). The projection helper that discovers inputs filters projected artifacts out, or the caller passes an explicit path.
- **Projection topology (Q2 - single Epic, 1:1 Stories):**
  - Exactly **one Epic per `ShapingResult`**. Multi-Epic grouping (a spec-set spanning several Epics) is **out of scope** (YAGNI; W1's real case is one goal = one Epic).
  - Exactly **one Story per `parcelSpecRef`**, in `parcelSpecRefs` order (1:1). No Story is invented that does not correspond to a referenced spec; no `parcelSpecRef` is dropped.
- **Title provenance (Q3 - honesty over convenience, no fabrication):**
  - **Story title** ← the referenced spec draft's frontmatter `title:` field, read via the **frozen** `spec-linter` `parseFrontmatter` (read-only relative-ESM import - no re-implementation that could drift). Each `parcelSpecRef` is a repo-relative POSIX path resolved against the repo root; the draft `.md` is read and its frontmatter parsed. **Refuse** (throw with a clear error naming the offending ref) if a referenced spec is missing, has no parseable frontmatter, or has a missing/empty `title:`. A `title:` is never fabricated or defaulted.
  - **Epic title** ← a **REQUIRED explicit `epicTitle` parameter** supplied by the caller (P3's approval flow / a human-facing path). There is **no derived fallback from the slug** (coordinator ruling Q3): `ShapingResult` carries no goal field and is frozen, and a silent slug-derivation would be exactly the fabricated-looking-complete value the empty-`epics` ruling exists to prevent. Refuse when `epicTitle` is absent, empty, or whitespace-only.
- **Key derivation (Q4 - provisional, pre-Jira placeholders):**
  - No Jira keys exist at projection time (registration is W1-P4). Keys are non-empty, stable, distinct **placeholders** that W1-P4 overwrites at registration.
  - **Story key** = the referenced spec's **filename stem** (basename minus the `.md` extension, e.g. `W1-P2-epic-story-projection`). Any string derivation from the path is **linear-time** (lesson #19).
  - **Epic key** = a provisional token derived from the artifact/session slug (the `<slug>` of the input `<slug>.shaping-result.json`).
  - **Never** use frontmatter `ticket:` for a key - every unregistered spec is `KONE-TBD`, which would collide across all Stories.
  - **Uniqueness guard:** duplicate Story keys (two `parcelSpecRefs` with the same filename stem) are refused with a clear error.
- **Output mechanics (Q5 - new sibling artifact, never in-place):**
  - Write a **new sibling artifact** at `plugins/foreman-line/docs/specs/active/<slug>.projected.shaping-result.json`, where `<slug>` is the input artifact's slug. The pristine W1-P1 `<slug>.shaping-result.json` (with `epics: []`) is **left intact** - this parcel **never mutates in place** (coordinator ruling Q5).
  - **`parcelSpecRefs` copied verbatim** from the input into the output (byte-for-byte; not re-derived, not re-normalized).
  - **Refuse to overwrite** an existing `<slug>.projected.shaping-result.json` (throw naming the colliding path), mirroring W1-P1's collision policy.
  - The emitted JSON is a plain object with no non-serializable values, written two-space-pretty with a trailing newline, **RFC 8785-canonicalizable** so W1-P3 can hash the approved artifact later. This parcel imports, vendors, and invokes **no** canonicalization/hashing code and mints **no receipt** (that is W1-P3's job).
  - A sibling `.projected.shaping-result.json` in `active/` never trips the spec-linter (it collects only `.md`).
- **Validation boundary + semantic guards (Q6 - schema-valid != semantically complete):** before write, the filled `ShapingResult` is re-validated against the imported frozen `shapingResultSchema`, **plus** four semantic guards (the frozen schema declares no `minItems` anywhere, so these are guards this package enforces), each with a rejecting fixture:
  - **(a)** `parcelSpecRefs` preserved verbatim from the input (a guard asserts the output's `parcelSpecRefs` deep-equals the input's).
  - **(b)** every input `parcelSpecRef` is represented by exactly one Story (no dropped or extra Stories).
  - **(c)** every Epic has `stories.length >= 1` (the single Epic is non-empty).
  - **(d)** the result's `epics.length >= 1` (a projection with empty `epics` is refused - the opposite of W1-P1's deliberately-empty `epics`).
- **Library-only; no CLI (Q8):** this parcel ships a **library surface only**. The CLI is **W1-P3's** surface (P3's approval flow invokes this package's projection function). Mirrors W1-P1 (library, no CLI) and keeps a single downstream CLI surface, avoiding a P2/P3 CLI overlap.
- **Linear-time string handling (lesson #19, up-front builder constraint):** any regex or string scan this package itself writes over untrusted text - the filename-stem / key derivation, slug handling, any path parsing - MUST be linear-time (no polynomial backtracking). Frontmatter parsing is delegated to frozen `spec-linter`; this parcel writes no regex over spec *body* text. CodeQL `js/polynomial-redos` is a required scanner and fires post-merge-assembly (lesson #19) - treat linear-time as build-time discipline, not a merge-time surprise.
- **Frozen contracts are untouchable:** `plugins/foreman-line/contracts/` (`ShapingResult`/`EpicNode`/`StoryNode`, `shapingResultSchema`, envelope types) and the shipped W0/W1-P1 packages (`shaping`, `spec-linter`, `schema-scaffold`, `routing-policy`, `receipts`, `skill-injection`, `permission-profiles`) are read-only reference. Any need to modify a frozen contract is a loop-stop, not a design option - in particular, any need for a **Task tier** below Epic/Story is a loop-stop (charter F1), not something this parcel introduces.
- **Branch/worktree (defects_lessons #9, #18):** builder works on named feature branch `feat/foreman-line-W1-P2`, isolated in worktree `C:\Repos\foreman-line-W1-P2`. The worktree is created by the `permission-profiles` dispatch-worktree emitter at dispatch time, **not by hand** (lesson #18 - pre-creating it collides with the emitter and forfeits its guarantees). This line goes into the dispatch kickstarter verbatim.
- **Deterministic-pass environment (defects_lessons #10, #11):** verification runs in PowerShell only. `node -v` is the first command run; repo-root and this package's `engines.node` (`>=24.11.1`) must be satisfied. Any exit-code check captures output in full before reading `$LASTEXITCODE` (never truncate a pipeline whose exit code is trusted, #11) - and never truncate any output a later step builds on (#17).
- **Install precondition:** because cross-package imports are relative with no workspace hoisting, run `npm install` in each consumed package before the deterministic pass: `plugins/foreman-line/projection/`, `plugins/foreman-line/shaping/`, `plugins/foreman-line/contracts/`, `plugins/foreman-line/spec-linter/`, and (transitively) `plugins/foreman-line/permission-profiles/` and `plugins/foreman-line/schema-scaffold/`. Same chain W1-P1's README documents.
