# W1-P1 - Shaping Agent

## Intent

Ship Stage A of the Foreman Line: the capability that turns a raw idea into linted parcel **spec drafts** plus a schema-valid `ShapingResult` handed forward to W1-P2. The deliverable is a split - a deterministic TypeScript package (`plugins/foreman-line/shaping/`) that emits and validates the `ShapingResult` and self-checks each draft against SPEC-CONVENTION, plus a skill (`skills/foreman-shaping/SKILL.md`) and a reusable dispatch kickstarter template that productize the interactive-shaping role. This parcel defines the P1->P2 handoff contract that everything downstream of intake consumes; it emits `ShapingResult` with an **empty `epics`** array that W1-P2 fills (charter F6), writes drafts at `status: draft` only, and mints no receipts and registers nothing (the two human gates and the receipt chain stay downstream).

## Constraints

- **Location:** `plugins/foreman-line/shaping/` in `kaseya-one-productivity-tools` (local: `C:\Repos\kaseya-one-productivity-tools`) - sibling to the frozen `plugins/foreman-line/contracts/` and the shipped W0 packages, same foundation tier. The skill ships at `skills/foreman-shaping/SKILL.md` (repo-level skills dir, matching the `/goal` skill precedent at `skills/goal/SKILL.md`); the reusable dispatch kickstarter template ships at `plugins/foreman-line/docs/kickstarters/foreman-shaping-template.md` (where shaping kickstarters already live).
- **Stack:** TypeScript, ESM-only. `engines.node >= 24.11.1` (repo-root precedent, defects_lessons #10 - NOT `>=22`; ratified Q2 correction). Tests via `node --test` (`npx tsx --test`). Lint/format with `biome`.
- **Standing rule (binding):** ajv's `JSONSchemaType` is banned as a schema authority anywhere in this repo; every schema is standard JSON Schema draft-07 typed as ajv's `SchemaObject`. This parcel authors **no new stage schema** - it consumes the frozen `shapingResultSchema` (`plugins/foreman-line/contracts/src/stages/a-intake.ts`) as its emission authority.
- **Runtime dependency allowlist:** exactly one runtime dependency - `ajv` (validation engine only). A test MUST assert `package.json`'s `dependencies` keys equal exactly `{ajv}`, machine-enforced per the W0-P3/W0-P4/SCAF-P1 pattern.
- **Shared scaffold, never copied (charter F9):** any `schemas/*.schema.json` generation this package needs consumes `plugins/foreman-line/schema-scaffold/` via a **filesystem-relative ESM specifier** (`import { generate } from '../../schema-scaffold/src/generate.js'`, `import type { SchemaFile } from '../../schema-scaffold/src/registry.js'`) with a local thin `src/generate.ts` wrapper and a local `src/registry.ts` holding this package's own `allSchemaFiles`. The bare specifier `@foreman-line/schema-scaffold` MUST NOT be used - no npm workspace linking exists across `plugins/foreman-line/*` (root `package.json` `workspaces` covers only `apps/*`/`packages/*`). Adding workspace linking to the root `package.json` is out of scope and a Stop-and-Report (SCAF-P1 / W0-P4 precedent). Note: this package authors no new schema, so a generator is required only if it exports a validation artifact needing a committed `schemas/*.schema.json`; if none is authored, no `generate.ts`/`schemas/` is added and this constraint is satisfied vacuously.
- **Cross-package imports (read-only consumption of already-exported surfaces, W0-P4 relative-ESM precedent):**
  - From `plugins/foreman-line/contracts/src/index.ts`: the `ShapingResult` type and `shapingResultSchema` (the frozen emission contract). Mechanism: `import ... from '../../contracts/src/index.js'` from modules under `shaping/src/`. `contracts/` is untouched.
  - From `plugins/foreman-line/spec-linter/src/index.ts`: `parseFrontmatter` and `validateSpecFrontmatter` (frozen frontmatter-validation surface) for the draft self-check. Mechanism: `import ... from '../../spec-linter/src/index.js'`. `spec-linter/` is **consumed, never modified** - it is shipped-frozen; this parcel adds no field, flag, or behavior to it.
  - Bare specifiers (`@foreman-line/contracts`, `@foreman-line/spec-linter`) MUST NOT be used (same non-resolution reason as the scaffold above). No new `dependencies` entry is required by the relative-import mechanism (W0-P4 precedent).
- **`ShapingResult` emission mechanics (the P1->P2 interface - the plan review's named under-specification, F6):**
  - **Shape:** the package emits the **bare `ShapingResult` payload** (`{ parcelSpecRefs, epics }`) validated against the frozen `shapingResultSchema` - NOT a `StageOutput<ShapingResult>` envelope. The envelope requires a `ReceiptRef`, and receipt minting is charter F8 -> W1-P3's approval flow; emitting an envelope here would preempt P3 and demand a receipt that does not exist at shaping time.
  - **`epics: []`** always at Stage A. This is schema-valid: `shapingResultSchema.epics` declares no `minItems` (verified against `a-intake.ts:32-35`). W1-P2 fills `epics` (F6).
  - **`parcelSpecRefs`:** repo-relative **POSIX-separator** paths to the emitted draft `.md` spec files, each `minLength: 1`. The frozen schema permits `parcelSpecRefs: []`, which is schema-valid but semantically wrong for Stage A; the emitter therefore applies a **semantic guard requiring `parcelSpecRefs.length >= 1`** and refuses to emit otherwise (schema-valid != semantically complete - this distinction is a named review focus below).
  - **Artifact location/naming:** exactly one `ShapingResult` JSON per shaping session at `plugins/foreman-line/docs/specs/active/<session-slug>.shaping-result.json`. The spec-linter only collects `.md` files, so a sibling `.json` in `active/` never trips it. (The goal-dir alternative was considered and rejected at shaping.)
  - **`<session-slug>` derivation and collision policy (coordinator-ratified amendment, 2026-07-22):** the emitter takes an explicit `sessionSlug` chosen by the caller; the package also exports a `deriveSessionSlug(raw: string)` helper - lowercase, trim, collapse each run of non-alphanumeric characters to a single `-`, strip leading/trailing `-`, and throw on an empty result. The emitter MUST refuse to overwrite an existing `<session-slug>.shaping-result.json` (throw with a clear error naming the colliding path); two shaping sessions can never silently collide - the caller picks a distinct slug.
  - **P1->P2 contract:** the **explicit path handoff is the contract** - W1-P2's input is the `ShapingResult` file path. The `plugins/foreman-line/docs/specs/active/*.shaping-result.json` glob is a **documented discovery fallback**, not the primary interface.
  - **Canonicalizability (F9/Q9 hook, build nothing):** the emitted JSON MUST be RFC 8785-canonicalizable (plain JSON object, no non-serializable values) so that W1-P3 can compute the genesis/Stage-A receipt hash over it later. This parcel writes the artifact in that shape and mints **no receipt**; it does not import, vendor, or invoke any canonicalization/hashing code (that is W1-P3 / pcc's job).
- **Spec-draft validation (ratified Q4):** the shaping package self-checks every draft it authors, in two layers, before emission:
  1. **Frontmatter:** via the imported `parseFrontmatter` + `validateSpecFrontmatter` from frozen `spec-linter` (v0.2 schema authority - `risk`/`surfaces`/`routing_class`, and the `permission_profile` advisory).
  2. **Body sections:** a **thin complementary check inside this package** confirming the SPEC-CONVENTION §4 required sections are present **and in order** (Intent, Constraints, Acceptance Criteria, Out of Scope, Context & References) and that **Out of Scope is non-empty** (§4.4). This check lives here, not in spec-linter (frozen).
  - **Authority statement (MUST appear in the shipped README and skill):** the package self-check is **advisory** - a fast local gate to cut round-trips. **Coordinator lint remains the sole authority**; a passing self-check never authorizes a `status` flip to `active`.
- **Skill + kickstarter template scope:** `skills/foreman-shaping/SKILL.md` describes the interactive-shaping session (clarify intent, surface constraints, propose decomposition, ask clarifying questions in small batches with recommended defaults, write drafts + emit `ShapingResult`, then STOP). The kickstarter template is a reusable dispatch shell for future shaping sessions. Neither the skill nor the template describes *this* session recursively - they describe the artifact/role, not the agent that built them.
- **Interaction contract (ratified Q5):** Inputs = a raw idea (required) + optional context references. Outputs = one or more spec drafts written to `plugins/foreman-line/docs/specs/active/` at `status: draft`, plus one `<session-slug>.shaping-result.json` with `epics: []`. **STOP boundary:** no `status` flips (draft->active), no `epics` projection-filling, no Jira registration, no receipt emission - mirroring the human dispatch gate (SPEC-CONVENTION §8; plan §2 Stage A human gate). Promotion to `active` is coordinator lint + Gate-2 authorization, downstream of this artifact.
- **Frozen contracts are untouchable:** `plugins/foreman-line/contracts/` (including `ShapingResult`/`EpicNode`/`StoryNode` and `shapingResultSchema` in `a-intake.ts`, and the envelope types) and the shipped W0 packages (`spec-linter`, `schema-scaffold`, `routing-policy`, `receipts`, `skill-injection`, `permission-profiles`) are read-only reference. Any need to modify a frozen contract is a loop-stop, not a design option - in particular, any need for a **Task tier** below Epic/Story is a loop-stop (charter F1), not something this parcel introduces.
- **Branch/worktree (defects_lessons #9):** builder works on named feature branch `feat/foreman-line-W1-P1`, isolated in worktree `C:\Repos\foreman-line-W1-P1` - never in the main working tree. This line goes into the dispatch kickstarter verbatim.
- **Deterministic-pass environment (defects_lessons #10, #11):** verification runs in PowerShell only. `node -v` is the first command run, before anything else; repo-root `package.json` `engines.node` requires `>=24.11.1` and this package's own `engines.node` (`>=24.11.1`) must be satisfied by whatever the coordinator's machine reports. Any exit-code check on a CLI invocation captures output in full before reading `$LASTEXITCODE` - never truncate a pipeline whose exit code is trusted.
- Integration is PR-only by standing policy; per SPEC-CONVENTION §3 this spec moves to `done/` in the same PR (or an immediate follow-up) as a merge-checklist item.

## Acceptance Criteria

1. `npx tsc --noEmit` passes on the `shaping` package.
2. The package exports a `ShapingResult` emitter that produces the **bare payload** (`{ parcelSpecRefs, epics }`), validated against the frozen `shapingResultSchema` imported from `contracts` (no local re-declaration of the schema or the type). A test asserts a produced artifact validates against `shapingResultSchema`.
3. Emitted `ShapingResult.epics` is `[]` (empty). A test asserts the empty-`epics` artifact is schema-valid (proving the frozen schema's no-`minItems` allowance is relied on deliberately, not by accident) - this is the "empty-epics validity" review focus, encoded as a test.
4. The emitter's **semantic guard** rejects emission when `parcelSpecRefs.length === 0`, with a clear error, even though such a payload is schema-valid; a passing fixture (>=1 ref) and a rejecting fixture (0 refs) both covered. `parcelSpecRefs` entries are repo-relative POSIX-separator paths; a test asserts separator normalization on a Windows-style input.
5. The emitted artifact is written to `plugins/foreman-line/docs/specs/active/<session-slug>.shaping-result.json`; a test asserts the path/naming convention (including the `<session-slug>` derivation) and that the file content is valid, parseable JSON.
6. **P1->P2 handoff:** an exported reader takes an explicit `ShapingResult` file path and returns the parsed, schema-validated payload (the primary contract); a documented `active/*.shaping-result.json` glob discovery helper is also exported (the fallback). Tests cover the explicit-path read (valid + rejects a schema-invalid file) and the glob discovery.
7. **RFC 8785 canonicalizability (Q9 hook):** a test asserts the emitted artifact is a plain JSON object with no non-serializable values (round-trips through `JSON.parse(JSON.stringify(x))` byte-stable under key insertion), so W1-P3 can hash it later. **No receipt is minted and no canonicalization/hashing code is imported** - a test/grep asserts zero import from `receipts/`, `skills/parcel-compiler/`, or any hashing utility.
8. **Draft frontmatter self-check** reuses the imported `parseFrontmatter` + `validateSpecFrontmatter` from frozen `spec-linter` (relative ESM specifier, no modification to `spec-linter`): a valid v0.2 draft passes; a draft missing a required v0.2 field (e.g. `risk`) is rejected with the linter's own violation surfaced. A test/grep confirms no file under `spec-linter/` is modified by this parcel.
9. **Draft body-section self-check** (this package's thin complementary check) confirms the SPEC-CONVENTION §4 required sections are present and in order (Intent, Constraints, Acceptance Criteria, Out of Scope, Context & References) and that Out of Scope is non-empty: a conformant draft passes; a draft with a missing section, out-of-order sections, or an empty/"None" Out of Scope is rejected. Each case has a fixture.
10. The self-check is **advisory-only** in behavior: it never writes, moves, or flips a spec's `status`; a test asserts the shaping flow leaves emitted drafts at `status: draft` and performs no folder move. The README and `SKILL.md` both state explicitly that coordinator lint is the sole authority.
11. `skills/foreman-shaping/SKILL.md` exists and documents the interactive-shaping session shape (inputs, small-batch clarifying questions with recommended defaults, outputs = drafts + `ShapingResult`, STOP boundary) without recursively describing this build session; `plugins/foreman-line/docs/kickstarters/foreman-shaping-template.md` exists as a reusable dispatch shell.
12. `package.json`'s `dependencies` keys equal exactly `{ajv}`, enforced by a test reading `package.json`.
13. No bare `@foreman-line/*` specifier appears anywhere in the package - grep-verified; root `package.json` is unmodified (`git diff --stat -- package.json` shows no change).
14. `biome check .` passes with zero diagnostics.
15. All tests pass via `npx tsx --test`; total test count >= 18.
16. `plugins/foreman-line/shaping/README.md` documents: the split (package + skill + kickstarter template), the bare-payload `ShapingResult` emission (why no envelope, empty `epics`, the `parcelSpecRefs` semantic guard), the artifact location/naming and the explicit-path P1->P2 contract with the glob fallback, the two-layer advisory self-check with the coordinator-lint-is-authority statement, the RFC 8785-canonicalizable "future genesis subject" note (receipt built by W1-P3, not here), and the relative-ESM import mechanism with the bare-specifier ban - in <= 2 pages.
