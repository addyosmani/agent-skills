# Plan-Level Adversarial Review — Permission-Profile Registry + Dispatch-Time Emitter

**Reviewer:** fresh, zero-context adversarial session (frontier), per `COORDINATOR-PATTERN.md` §"Plan-level adversarial review — always".
**Subject:** `docs/goals/permission-profile-registry/charter.md` (Gate-1 ratified 2026-07-16, incl. D9).
**Date:** 2026-07-16.
**Verdict in one line:** the decomposition is largely coherent and the parcel boundaries are mostly real, but the goal's *headline claim* — that a permission profile turns "reviewer never fixes/commits" into a **missing capability** — is not established by the plan as written. Two independent, load-bearing mechanisms (the session-launch mode that decides whether the emitted file is even read, and the Bash escape hatch that deny-Edit/Write does not cover) are unexamined, and P3's live-probe AC as described can go green while proving neither. Details below.

Legend for disposition column: **fix** = change the charter/parcel scope before shaping; **accept-as-documented** = keep the decision, record the limitation honestly; **informational** = coordinator awareness, no charter change required.

## One-paragraph summary for the coordinator

My top three findings are all about the same thing the prior thread already got burned on — an envelope that validates clean but does not bite. **(1, F-A)** The entire mechanism assumes a builder session re-loads `.claude/settings.local.json` from its worktree at start; that is true for a top-level `claude` CLI launch but false for a Task-tool background subagent (which shares the coordinator's settings) and void under bypass-permissions mode — and this repo's own loop directive describes builders as background agents and runs the coordinator in bypass. The charter must pin the exact launch mechanism and require P3's probe to use it, or the whole goal is a day-one placebo. **(2, F-B)** Deny-`Edit`/`Write` is not deny-filesystem-mutation: a reviewer with `Bash` (which lesson #12 requires for hostile-input probing) can still `git commit`, `git push`, and `echo > file`, so "reviewer never fixes/commits" remains a directive, not a missing capability, and the `.claude/**` self-modification guard is Bash-bypassable — P3's probe must attempt a Bash write/commit, not just a Write-tool write. **(3, F-C)** P3's headline AC has no positive control, so it greens if the write failed for any incidental reason; require the same write to *succeed* under `builder-standard` and only be *denied* under `reviewer-readonly` so the denial is attributable to the envelope. Two smaller but concrete fixes worth doing in the same pass: D9's "won't ride a PR" guarantee currently depends on Clint's machine-local global gitignore, not a repo-tracked `.gitignore` (F-D), and the P2 stop-condition wording literally forbids the schema/parity-test edits P2 requires (F-F).
