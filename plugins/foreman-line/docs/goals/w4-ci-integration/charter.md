## Objective

Ship Wave 4 of the Foreman Line (FOREMAN-LINE-PLAN.md §8, "W4 — CI Integration"): the pipeline's **Stage E (Integration)** and **Stage F (Closure)** capability — an agent commits/pushes/opens a PR under branch protection it cannot bypass → DocSpine validates documentation claims against the diff → risk-driven audit triggers fire deterministically from declared (`risk:`/`surfaces:`) + derived (diff) inputs, blocking on drift → GitHub gate assembly requires scans + human review → on human merge the Jira ticket transitions to closed and the receipt chain is sealed. Built parcel by parcel under PDD against the frozen W0 contracts and the shipped W1/W2/W3 machinery.

## Exit criterion  *(AMENDED per PR4-1/2/3/7 — RE-RATIFIED 2026-07-26)*

**SCAF-P4** — a bounded parcel declaring `risk: elevated` matching a genuinely elevated surface (see D6) — travels **Stage E–F end-to-end** through the W1/W2/W3/W4 machinery, subject to these explicit, ratified conditions:

1. **Branch protection is a verified precondition, not an optional step (PR4-1).** Before SCAF-P4's PR is opened, the repo's require-PR / required-checks ruleset is confirmed — via the GitHub **effective-rules API** (lesson #15) — to bind *even the coordinator's identity*. "Agents cannot merge" is proven by configuration, not asserted.
2. **The human merge is a structural, non-delegable exit dependency (PR4-1).** Gate-3 standing authorization does **not** auto-merge SCAF-P4; a human performs the merge. This goal cannot reach "complete" without that human action, by design.
3. **Audit trigger — decision proven live, blocking-run out of scope (PR4-2/4).** SCAF-P4's live PR exercises the deterministic `max(declared,derived)` trigger *decision* + receipt on its elevated surface (declared = elevated, **no drift** → a clean pass that can merge). The **drift-block behavior is proven at the harness/unit level** (SCAF-P4 carries ≥3 harness-checkable ACs including a declared-vs-derived-*mismatch* case the harness blocks). The actual audit *run* + finding-based PR block are a named follow-on (W4-FUP-AUDIT, per D5) — out of W4 scope.
4. **"Blocking" is a second, human-gated phase (PR4-7).** The W4 checks run **report-only** first; their promotion to *required status* is a named human stop-and-present ruleset change (D8). The exit's "gates the PR" behavior is demonstrated only after that promotion — report-only and blocking are two ordered phases, not one.
5. **DocSpine leg is conditionally satisfiable (PR4-3).** DocSpine validation runs against a **named, pinned DocSpine entry-point commit** and validates doc claims against **repo state** (its actual v0.1.0 capability — not "the diff"). If the §7a org transfer / interface finalization has not landed, the DocSpine leg is stubbed-and-reported and the exit is satisfied for **every stage whose external dependency is live**.
6. **Chain sealed and `validateChain`-valid (PR4-8).** On human merge: the Jira ticket transitions to closed via MCP; the spec moves `active/ → done/`; the Stage-F closure receipt seals the chain. The receipt chain over the **freshly-minted SCAF-P4 A→F chain** passes `validateChain` (AC5c correlation invariant end-to-end), not merely `walkChain`. Pre-fix on-disk chains are orphaned/non-migratable and are not in scope. Zero self-graded claims anywhere.

## Stop conditions

Universal (COORDINATOR-PATTERN): a frozen contract needs modification; a tripwire fires twice on one parcel; a security finding can't close in-parcel; anything outward-facing beyond the standing authorizations; queue empty.

Goal-specific:
- Any live-workflow or branch-protection/ruleset change beyond the D8 carve-out surfaces → stop and present a human-applied diff, never self-apply.
- W4-P0 correlation fix requires modifying a frozen W0 contract (not just the dispatch package) → loop-stop.
