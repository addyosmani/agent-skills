## Objective

Ship Wave 3 of the Foreman Line (FOREMAN-LINE-PLAN.md §8, "W3 — Verification"): the pipeline's Stage D capability — harness runs acceptance criteria as executable checks → adversarial reviewer session is orchestrated (not self-graded) → rework routing escalates mechanically if checks fail → human approves → Jira ticket updated — built parcel by parcel under PDD against the frozen W0 contracts, W1/W2 packages, and the shipped dispatch machinery.

## Exit criterion

A real parcel — SCAF-P3 (to be shaped at W3 loop start, registered via W1 Jira machinery, dispatched via W2 dispatch machinery) — verified through the complete W3 Stage-D machinery: harness runs SCAF-P3's acceptance criteria as executable checks and returns a passing receipt; the adversarial reviewer session is auto-orchestrated (W3-P2), armed with the code-review skill, and returns findings; the coordinator triages and (on clean triage) the chain advances — with the mechanical rule (PRF-9) that adversarial findings of severity ≥ high block regardless of coordinator triage; coordinator disposition applies only below that line; the human-review gate (W3-P4) presents the summary for one-tap approval; on approval the Jira ticket transitions and the Stage-D closure receipt is emitted. The receipt chain must be walkable: genesis → Stage-A → Stage-B → Stage-C (W2) → Stage-D (W3). Zero self-graded claims anywhere in the chain.

## Stop conditions

Universal set (COORDINATOR-PATTERN): a frozen contract needs modification; a tripwire fires twice on one parcel; a security finding can't close in-parcel; anything outward-facing beyond the standing authorizations; queue empty.

Goal-specific additions:
- Rework cap exceeded (third failure on one parcel) — stop, structured failure report to Clint; no third rework without explicit authorization.
- W3-P2 automated dispatch violates D4 (coordinator context leaks into the reviewer session) — stop; this is an architectural invariant, not a rework item.
